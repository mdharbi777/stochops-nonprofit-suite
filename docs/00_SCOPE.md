# 00 — النطاق والافتراضات (SCOPE)

> مثبّت من خطة البناء الرئيسية (إصدار 1.0 — 17 أكتوبر 2026). هذا الملف هو مرجع النطاق الملزم. أي خلاف يُحسم لصالح هذا الملف وخطة البناء، وأي إضافة خارجه تُسجّل في [BACKLOG](BACKLOG.md) فقط.

## 1. هوية المنتج
- **الاسم:** STOCHOPS Nonprofit Operations Suite (NOS).
- **الاسم التقني:** تطبيق Frappe مخصّص `stochops_nonprofit`.
- **الطبيعة:** منتج داخلي لإدارة العمليات، واجهة عربية RTL أولاً (الإنجليزية خيار لاحق وليست شرط إطلاق).
- **المستخدم المستهدف:** الموظف الإداري في الجمعية.
- **أول عميل تجريبي:** جمعية الإخلاص — تطوير مجاني ضمن نطاق تجريبي، بيانات وهمية فقط.

## 2. الوحدات المشمولة (ثلاث فقط، بالترتيب الصارم)
1. **القرارات واللجان** — تسجيل الاجتماعات والقرارات وإسناد المسؤوليات ومتابعة التنفيذ. → GATE 1
2. **البرامج والمبادرات** — تتبع أهداف المبادرات والمهام والموازنة الإدارية (إجمالي مخطط/مصروف) والمخرجات. → GATE 2
3. **المؤشرات والتقارير** — تقارير وملخص تنفيذي مستمدة من الوحدتين السابقتين دون إدخال مزدوج. → GATE 3

**مبدأ التنفيذ:** وحدة واحدة فقط قيد العمل في أي لحظة. لا تبدأ الثانية قبل اجتياز اختبارات وقبول الأولى (Gate)، ولا الثالثة قبل الثانية.

## 3. خارج النطاق صراحةً (MVP)
- بوابة مستفيدين، منصة/بوابة تبرعات، نظام رواتب، محاسبة عامة، نظام مشتريات/عقود.
- CRM، موقع تسويقي منفصل.
- تكامل مع جهات حكومية أو بنكية.
- تخزين **أسماء مستفيدين أو أرقام هويات أو بيانات أسر أو حالة اجتماعية** (ممنوع نهائياً).
- إدارة اشتراكات/فواتير العملاء وتسعير تجاري.
- بناء نظام صلاحيات/تفويض مخصّص موازٍ لـ Frappe.
- بناء `Charity` DocType متعدد العملاء داخل قاعدة واحدة (نستخدم موقعاً مستقلاً لكل جمعية بدلاً منه).

أي بند أعلاه، أو أي فكرة جديدة → [BACKLOG](BACKLOG.md) بدون تنفيذ.

## 4. الافتراضات (مبدئية حتى التحقق الميداني)
- لا نفترض أن للجمعية نظاماً حالياً معيّناً، ولا موظفين محددين، ولا مشاكل موثّقة؛ التحقق الميداني لاحق.
- كيان «جمعية الإخلاص» يظهر فقط في بيانات تجريبية اختيارية، دون معلومات حساسة أو شعارات أو ملفات فعلية بلا تفويض.
- لا نُنسب للجمعية موافقة على المنتج حتى تُوثّق.
- بيئة التطوير قد تكون محلية (جهاز المطوّر) أو كود/اختبارات ساكنة إذا تعذّر تشغيل Frappe فعلياً — مع التصريح الصريح بحالة التحقق.

## 5. الحدود الثابتة (مبادئ لا تُخالَف)
- **صفر إنفاق** في التطوير: لا خدمة مدفوعة، ولا Trial يتطلب بطاقة، ولا API بمقابل، ولا استضافة خارجية، ولا SMS، قبل موافقة صريحة مكتوبة.
- لا تكرار لما يوفّره Frappe أصلاً (مستخدمون، أدوار، مرفقات، سجلات تغيير، تقارير، تنبيهات).
- جميع أرقام لوحات المعلومات من queries/DocTypes، لا من إجابات LLM.
- الأفضل الإلغاء/الأرشفة بدل الحذف النهائي؛ والحذف الحساس بدور إداري فقط.
- لا استيراد تلقائي لمستندات داخلية ولا توصيل بنظام خارجي قبل موافقة الجمعية.
- لا ادّعاء اعتمادات حكومية أو شراكات رسمية.

## 6. تعدّد الجمعيات
موقع Frappe **مستقل لكل جمعية** (`one site / one charity`) مع تطبيق برمجي واحد مشترك؛ قاعدة بيانات وأسرار ومرفقات ونسخ احتياطية مستقلة لكل موقع. إعدادات `Nonprofit Settings` لكل موقع (الاسم، الشعار المأذون، المنطقة الزمنية Asia/Riyadh، صيغة التواريخ، لغة الواجهة، بيانات تواصل داخلية).

## 7. التسلسل التنفيذي
| Sprint | المحتوى |
|---|---|
| 0 | الوثائق + الهيكل + البيئة المحلية + أدوار أولية + اختبار تثبيت |
| 1 | الوحدة 1 فقط + اختبارات + **GATE 1** |
| 2 | الوحدة 2 فقط + اختبارات + **GATE 2** |
| 3 | الوحدة 3 فقط + اختبارات + **GATE 3** |
| 4 | ضمان الجودة والأمان والتوثيق وحزمة النقل |
| 5 (مؤجّل) | نشر على استضافة داخل السعودية يوفّرها المالك |
| 6 (اختياري مؤجّل) | تفعيل AI بموافقة وتكلفة محددة |

لا وعود زمنية أو مالية دقيقة قبل قياس سرعة التطوير والجهاز والبيئة.

## 8. حالة هذا المستند
Sprint 0 — مكتمل كنطاق مبدئي مثبّت. يُحدّث فقط بقرار موثّق من المالك.
