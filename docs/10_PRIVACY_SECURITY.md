# 10 — الخصوصية والأمان (PRIVACY & SECURITY)

## حالة البيانات
- **التطوير:** بيانات وهمية فقط — بدون أرقام هويات أو حسابات مصرفية أو بيانات مستفيدين أو ملفات اجتماعية.
- **قبل الإنتاج:** اتفاق يحدّد مسؤولية الجمعية وSTOCHOPS عن التحكم/المعالجة/الوصول/الدعم/الحذف/النقل، ومراجعة متطلبات **نظام حماية البيانات الشخصية السعودي (PDPL)** بحسب نوع البيانات والأطراف الفعلية.

## متطلبات أمان لا تُؤجَّل
- صلاحيات مفروضة **على الخادم** (وليس UI فقط) على السجلات والتقارير والملفات.
- HTTPS في الإنتاج؛ عدم كشف MariaDB/Redis مباشرة على الإنترنت.
- كلمات مرور قوية وحسابات فردية؛ MFA إن دعمته البيئة بموثوقية.
- الأسرار عبر البيئة/secret manager — **لا في مصدر GitHub**.
- سجل أحداث وتغييرات مهم؛ سياسة الاحتفاظ تُحدَّد لاحقاً مع الجمعية.
- حماية من حقن المدخلات/XSS عبر أدوات Frappe الافتراضية + اختبارات.
- تحديثات أمنية مع اختبار على staging قبل production.
- فحص dependencies وأسرار git قبل أي release.

## قواعد AI (عند التفعيل لاحقاً فقط)
- `ai_enabled=false` افتراضياً؛ التفعيل يتطلب موافقة مكتوبة على نوع البيانات والمزوّد ومنطقة المعالجة والشروط.
- إرسال الحد الأدنى من البيانات المصرّح بها فقط؛ لا مرفقات ولا أسماء مستفيدين.
- مراجعة واعتماد بشري لكل نص قبل الحفظ كسجل نهائي.
- اختبارات منع prompt injection ومنع تجاوز صلاحيات المستخدم.
- تسجيل تشغيل الوظيفة وحالة النتيجة **دون** تخزين أسرار أو payload حساس في logs.

## حدود GitHub
GitHub يحفظ الكود/الوثائق فقط. **يُحظر** اعتباره استضافة لتطبيق Frappe حي أو مخزناً لقاعدة MariaDB. لا ترفع `.env`، `sites/`، نسخاً احتياطية، ملفات خاصة، أو أي أسرار.
