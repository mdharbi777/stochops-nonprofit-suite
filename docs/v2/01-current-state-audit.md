## 2. الصلاحيات والعزل (مُتحقَّق)
- **عزل المستأجر:** `permission_query_conditions` + `has_permission` + `before_insert set_charity` على ~26 نوعاً → deny-by-default للقراءة/الكتابة عبر client API. ✅
- **ACL على مستوى الحالة:** `Beneficiary` و`Assistance Request` عبر `case_worker` + `has_case_permission`. ✅
- **الأدوار:** Nonprofit Admin / Executive Viewer / Committee Coordinator / Program Coordinator (4). **ناقص** مقابل §6: مسؤول مستفيدين/برامج/منح/مالية/مشتريات/HR/حوكمة/عضو لجنة/مدقق.
- **فجوة:** لا **مصفوفة صلاحيات** صريحة (module×resource×action×scope×state×amount) كما §6.2 — الصلاحيات موزّعة في hooks + permissions لكل DocType.

## 4. ما أُنجز فعلاً في P1 (هيكل الواجهة — قبل هذه المواصفات)
- `AppShell` مشترك (`public/nos/shell.css/js`): قائمة جانبية يمين RTL مجمّعة + شريط علوي + breadcrumb + تجاوب، مُطبّق على 23 صفحة. ✅
- إصلاح كاش (`no_cache`) للصفحات المعتمدة على الجلسة. ✅
- **ملاحظة امتثال للمواصفات §0.1:** الهيكل الحالي **يستخدم رموزاً تعبيرية** في القائمة الجانبية — **مخالف** لبند «ممنوع الأيقونات/الرموز»؛ يجب استبدالها بنصوص/رموز نصية محايدة في P1-التصحيح.

## 5. مخاطر مُوثَّقة
- الاستضافة الحالية **خارج السعودية** (مؤقّت) — إقامة البيانات غير مُحقَّقة (تعاقدياً/تقنياً) ⇒ لا بيانات حقيقية.
- 2GB رام (t3.small) أثبتت هشاشة تحت الضغط ⇒ الإنتاج يحتاج استضافة سعودية أكبر.
- الجلسات تُفقد عند إعادة البناء (recreate redis) ⇒ مقبول للتجربة.
- **لا يوجد تصدير محوكم** ⇒ فجوة امتثال/تشغيل أساسية في V2.

## 6. قرار
الأساس الخلفي (بيانات/عزل/PDPL/اختبارات) **متين وصالح للبناء عليه**. لا حاجة لإعادة بناء جذرية.
الفجوات في **طبقة التجربة والتقارير وسير العمل**. ⇒ المضي في P1(تصحيح)→P2→P3→P4 بالترتيب، مع تصميم RBAC ونموذج التقارير مبكراً (§12).
