> خريطة الوحدات والقوائم والمسارات والعلاقات، وفق §3 و§4 من مواصفات V2.
> المبدأ: القائمة تعرض **المتاح فعلياً**؛ الناقص يُسجَّل كمهمة تنفيذ لا رابطاً ميتاً.

## 2. مبادئ التنقّل (V2)
- القائمة الجانبية **تعكس دور المستخدم** (تعرض ما يحقّ له فقط) — *(حالياً تعرض الكل: فجوة P1/P3).*
- `Breadcrumbs` حقيقية: الوحدة ← القائمة ← السجل.
- حفظ السياق (فلاتر/تبويب/صفحة) عند تغيير المسار + رابط عودة.
- الرابط المباشر لسجل محمي يعمل **بعد التحقق** (deny-by-default).
- لا روابط ميتة: الوحدة غير الجاهزة تظهر كـ«قيد التجهيز» لا كصفحة إنتاج.

## 3. العلاقات بين السجلات (نموذج التشغيل §4)
```
مستفيد → ملف حالة → تقييم أهلية → طلب مساعدة → قرار → اعتماد → صرف/تسليم → إثبات → إغلاق/متابعة
مانح/منحة → التزام → تخصيص لبرنامج → استخدام مقيّد → دليل صرف → تقرير المانح
طلب شراء → عروض الموردين → مقارنة → اعتماد → أمر شراء → استلام → مصروف مرتبط (بلا ازدواج)
اجتماع لجنة → محضر → قرار → مسؤول → موعد → إثبات → إقفال/تصعيد
طلب موظف/إداري → صاحب الصلاحية → اعتماد → تنفيذ → أثر في السجل
```
- كل علاقة **ثنائية الاتجاه**: من المستفيد تظهر مساعداته؛ من المساعدة يُفتح ملفه (للمخوّل فقط).
- **معرّفات:** UUID داخلي + مرجع بشري فريد لكل جمعية (`BEN-2026-0001`). **لا** الرقم الوطني كمفتاح. ✅ (الحالي يلتزم).
- **الحالة الحالية:** العلاقات الأساسية موجودة (قرار↔اجتماع↔لجنة، مصروف↔جمعية)، لكن سلاسل (أهلية/صرف/إثبات) و**صفحات التفاصيل ثنائية الاتجاه** ناقصة ⇒ P2.

## 4. قالب الصفحة الموحّد (المستهدف §2.3)
1) مسار/عنوان/وصف → 2) إجراءات رئيسية حسب الدور/الحالة → 3) ملخّص من بيانات فعلية →
4) بحث/فلاتر/تاريخ/محدّد أعمدة → 5) جدول (فرز + ترقيم خادمي + تحديد صفوف) →
6) صفحة تفاصيل بأقسام/Tabs → 7) نشاط/مرفقات/اعتمادات/سجل → 8) تصدير Excel/PDF + عدّاد + وقت التحديث.

*(الحالي ينفّذ 1–3 و5(جزئياً)؛ 4،6،7،8 فجوات P2/P4.)*
