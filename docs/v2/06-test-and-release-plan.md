# P0 — خطة الاختبار والقبول والإطلاق والتراجع

> وفق §10، §11، §13، §14 من مواصفات V2. العدد وحده ليس معيار الجودة.

## 1. خط الأساس الحالي (مُتحقَّق)
- **109 اختباراً آلياً / 16 ملفاً** (unit + isolation + notifications + privacy/gate). تمرّ 109/109.
- تغطية حالية: عزل المستأجر، ACL حالة، منطق القرارات، بوابة PDPL، كشف الهوية، الإشعارات.
- **فجوات اختبار V2:** authorization سلبي شامل على API/export، cross-tenant لكل نقطة دخول، E2E لرحلات §11، تحقق مخرجات التصدير، أداء، backup-restore آلي.

## 2. أنواع الاختبار المطلوبة (§13)
unit · integration · **API authorization (سلبي)** · **cross-tenant isolation** · E2E · **export verification** · performance (بعد baseline) · backup-restore.

## 3. رحلات E2E الإلزامية (§11) — حالتها
| # | الرحلة | الحالة |
|---|---|---|
| 1 | مسؤول جديد: تسجيل→تحقق→هوية→دعوة→دور→رؤية صفحات دوره فقط | **جزئي** (تسجيل/دعوة موجود · رؤية حسب الدور ناقصة) |
| 2 | مسؤول مستفيدين: تسجيل→ملف→مرفق آمن→طلب→مسودة→إرسال | **جزئي** (مرفق/مسودة/ملف ناقص) |
| 3 | مراجع: ظهور في «مهامي»→فتح→استكمال/رفض/اعتماد→تحديث فوري+إشعار | **ناقص** (محرك مراجعة) |
| 4 | منفذ: قرار معتمد→توثيق صرف→إثبات→إغلاق، بلا تجاوز اعتماد | **ناقص** |
| 5 | مشتريات: طلب→مقارنة→اعتماد بحدّ→أمر→استلام→ربط مصروف | **ناقص** |
| 6 | حوكمة: قرار لجنة→مسؤول/موعد→تنبيه→إثبات→إغلاق | **جزئي** (الأساس موجود) |
| 7 | مدير: لوحة→قائمة خلف الرقم→تصفية→تصدير Excel/PDF مطابق | **ناقص** (تصدير) |
| 8 | غير مخوّل: فتح URL/API/سجل/مرفق/تصدير لجمعية/دور آخر→رفض بلا تسريب | **جزئي** (query موجود · اختبار شامل ناقص) |
| 9 | هاتف: إنجاز طلب كامل بلا قصّ/إخفاء/تمرير أفقي | **ناقص** |
| 10 | خطأ واقعي: فشل شبكة/انتهاء جلسة/تعارض/فشل تقرير بلا فقد/تكرار | **ناقص** (حالات واجهة موحّدة) |

## 4. الأمن (§10) — مرجع OWASP ASVS 5.0
اختبار مستقل: access control لكل route/API، IDOR، CSRF، XSS، injection، file up/download، secrets، rate limit، session expiration، multi-tenant، Audit. *(فحص ZAP المجاني مُخطّط — لم يُنفَّذ بعد.)*

## 5. الخصوصية والاستضافة (§10) — حالة تحقّق لا إقرار
- PDPL: الأساس مبني (غرض/حدّ أدنى/حقوق/احتفاظ/حوادث/معالجون فرعيون/سجل معالجة)، لكن **الامتثال حالة تشغيلية/تعاقدية تُثبَت بالتدقيق**، لا بالكود وحده.
- **إقامة البيانات داخل السعودية غير مُحقَّقة حالياً** (الاستضافة AWS خارجية مؤقتة) — تشمل التحقق: الخوادم + النسخ + السجلات + المرفقات + المزوّدون الفرعيون.
- التشغيل الفعلي ببيانات حقيقية ⇒ DPA/DPIA + استضافة سعودية مُحقَّقة + فتح البوابة + سجل أدلة موافقات.

## 6. خطة الإطلاق والتراجع
- **Staging** منفصل + بيانات مصطنعة ممثّلة (لا بيانات إنتاج في التطوير/السجلات).
- نشر تدريجي لكل مرحلة + **نسخة احتياطية قابلة للاسترجاع قبل أي migration** + migrations قابلة للرجوع.
- rollback: استعادة الصورة/النسخة السابقة + توثيق RPO/RTO المتفق عليها مع المالك.
- **تقرير تقدّم إلزامي** بنهاية كل مرحلة (جدول §14) + قرار Go/No-Go صريح.

## 7. بوابات القبول لكل مرحلة (§12)
- **P1:** كل مسارات /nos تستخدم الهيكل ذاته · لا أزرار معطلة/صفحات يتيمة · **بلا أيقونات/رموز** (§0.1).
- **P2:** رحلة مستخدم متكاملة بلا إدخال مكرر ولا عودة يدوية للرئيسية.
- **P3:** رفض عمليات غير مخوّلة على UI/API/export · لا تجاوز حدود · لا موافقة ذاتية.
- **P4:** تطابق أرقام التقارير + تصدير Excel/PDF صالح عربي + لا تسرّب.
- **P5:** جمعية تجريبية تُكمل الإعداد والرحلات بلا مطوّر.
- **P6:** أدلة أمن/تحميل/استرجاع + تحقق استضافة/معالجين + DPA/DPIA + إقرار المخاطر قبل بيانات حقيقية.
