# 07 — النسخ الاحتياطي والاستعادة (BACKUP & RESTORE)

## أثناء التطوير
- نسخ محلية تجريبية عند الحاجة فقط.
- **لا تُرفع نسخ قواعد البيانات إلى GitHub** إطلاقاً (مغطّى في `.gitignore`).

## قبل الإنتاج (مؤجّل — سياسة مطلوبة)
- نسخ احتياطي **آلي** لقاعدة البيانات والملفات الخاصة/العامة المشروعة.
- النسخ **مشفّرة** ومخزّنة في مكان مستقل ومصرّح به.
- **تجربة restore حقيقية قبل الإطلاق** — يُسجّل نتيجتها وتاريخها هنا.
- احتفاظ/تدوير، تحقّق من مساحة النسخ، إنذار للفشل، اختبار صلاحيات الوصول.
- لكل جمعية: موقع مستقل + نسخ احتياطي مستقل + إجراء استعادة مستقل.

## أوامر النسخ الاحتياطي (frappe/bench)
```bash
# نسخة قاعدة البيانات + الملفات الخاصة والعامة
bench --site <site> backup --with-files
```
- تُحفظ في `sites/<site>/private/backups/`. تُنقَل **مشفّرة** إلى تخزين مستقل ومصرّح به (لا GitHub).
- **جدولة آلية:** cron على الخادم (أو إعداد نسخ دوري) + تدوير/احتفاظ + إنذار للفشل + تحقّق من المساحة.

## أوامر الاستعادة
```bash
bench --site <site> restore <db.sql.gz> \
  --with-public-files <public-files.tar> \
  --with-private-files <private-files.tar>
bench --site <site> migrate
```
- نفّذ **تجربة استعادة حقيقية على staging** قبل أي إطلاق إنتاجي، وسجّل النتيجة أدناه.
- لكل جمعية: موقع ونسخ احتياطي واستعادة **مستقلة** تماماً.
