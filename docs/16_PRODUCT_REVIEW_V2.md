# 16 — مراجعة المنتج ونموذج العمل + خارطة v2 (تماسك المنتج)

> مراجعة صادقة بعد أول تشغيل حيّ على `alfadil.stochops.com`. الغرض: تأطير قيمة المنتج،
> وتحديد فجوات التجربة، ورسم خارطة v2 لجعل المنصّة «نظاماً واحداً متماسكاً» لا صفحات منفصلة.

---

## 1. الملخّص التنفيذي
**منصة الفاضل ليست ERP عاماً — وهذا مقصود.** هي **منصة حوكمة + امتثال + عمليات للجمعيات الخيرية السعودية**،
عربية أصيلة، متوافقة مع PDPL، بإقامة بيانات سعودية.

- **الأساس الخلفي قويّ ومتين فعلاً** (نموذج بيانات ناضج، صلاحيات على الخادم، عزل مستأجرين، طبقة PDPL، 109 اختبار).
- **الفجوة في طبقة التجربة (/nos):** صفحات مبنية يدوياً بلا «هيكل تطبيق» موحّد → تُحسّ كصفحات لا كنظام.
- **الخلاصة:** المحتوى موجود؛ المطلوب **تماسك التجربة** (تنقّل موحّد، إدارة فريق واضحة، تناسق بصري).

---

## 2. نموذج العمل

| البُعد | الوصف |
|---|---|
| **الفئة المستهدفة** | الجمعيات الخيرية السعودية التي لا تحتمل تعقيد/تكلفة ERP كامل |
| **القيمة الأساسية** | نظام سهل + عربي + محوكم + متوافق PDPL يغطّي العمل الأساسي، بدل Excel المبعثر أو ERP ثقيل |
| **التمايز** | عربية أصيلة · **PDPL وإقامة بيانات سعودية مدمجة** · حوكمة (لجان/قرارات/التزامات) · بساطة مقصودة |
| **التغطية** | المستفيدون والمساعدات · المتبرعون/المنح · المصروفات بضوابط · الموارد البشرية · المشتريات · الخصوصية والحوكمة |
| **عدم النطاق (مقصود)** | لا بوابة دفع · لا محاسبة مزدوجة · لا رواتب — يبقيها بسيطة ومتوافقة (تكامل لاحقاً) |
| **النموذج الربحي** | SaaS متعدّد المستأجرين · اشتراك شهري للجمعية · تسجيل ذاتي · حتى 5 حسابات للجمعية |
| **الاستضافة** | داخل السعودية (إقامة بيانات) — شرط التشغيل الفعلي مع DPA + DPIA + فتح البوابة |

**لماذا هذا قيّم؟** المنافس (ERP عام مثل Odoo/ERPNext) معقّد وباهظ ولا يفهم السياق السعودي ولا PDPL.
المنافس الواقعي (Excel/ورق) فوضوي وغير محوكم وغير متوافق. منصة الفاضل تملأ الفجوة: **بساطة + حوكمة + امتثال عربي سعودي.**

---

## 3. تقييم الحالة الحالية

### نقاط القوة (جاهزة ومتينة)
- نموذج بيانات شامل (33 نوع مستند) يغطّي كل الوحدات.
- صلاحيات مفروضة على الخادم + عزل بين الجمعيات + ACL على مستوى الحالة.
- طبقة PDPL كاملة (بوابة إنتاج، تشفير الهوية، سجل اطلاع، حقوق الأفراد، احتفاظ، حوادث).
- ضوابط مالية (فصل الصلاحيات، حدود الاعتماد)، مساعد ذكي محاكاة، إشعارات.
- 109 اختبار آلي ناجح.

### الفجوات (طبقة التجربة)
| الفجوة | الوصف | الأثر |
|---|---|---|
| **تنقّل غير موحّد** | لا قائمة جانبية ثابتة ولا breadcrumbs؛ التنقّل يعتمد على العودة للوحة الرئيسية | يُحسّ «صفحات» لا «نظام» |
| **إدارة الفريق والصلاحيات** | موجودة في «إدارة الحسابات» لكنها بسيطة وغير بارزة، بلا مصفوفة صلاحيات واضحة | غموض «من يصل لماذا» |
| **تناسق بصري وحالات** | اختلاف بسيط بين الصفحات؛ حالات (تحميل/فراغ/خطأ) غير موحّدة | انطباع أقل احترافية |
| **تهيئة أولى (Onboarding)** | لا مسار موجّه لجمعية جديدة (هوية، دعوة فريق، جولة) | بداية مربكة للجمعية |
| **التجاوب مع الجوال** | يحتاج ضبطاً للشاشات الصغيرة | وصول محدود |

## 4. خارطة v2 — «تماسك المنتج»

> المبدأ: لا نضيف وحدات جديدة الآن؛ **نرفع تماسك ونضج ما هو موجود** حتى يُحسّ نظاماً واحداً.

### المرحلة A — هيكل تطبيق موحّد (App Shell) ⟵ الأعلى أثراً
- **قائمة جانبية ثابتة** بكل الوحدات (قابلة للطي)، تُبرز الوحدة الحالية.
- **شريط علوي موحّد**: اسم الجمعية، المستخدم، الإشعارات (الجرس)، خروج.
- **مسار تنقّل (breadcrumbs)** + عنوان صفحة موحّد.
- يُطبّق على كل صفحات /nos عبر قالب/مكوّن مشترك.

### المرحلة B — الفريق والصلاحيات
- شاشة «الفريق» واضحة: الحسابات الخمسة، حالتها، أدوارها، دعوة/تعطيل.
- **مصفوفة صلاحيات** مقروءة: الأدوار × الوحدات (من يرى/يعدّل ماذا).

### المرحلة C — التهيئة الأولى والتناسق
- مسار أول دخول لجمعية جديدة: هوية الجمعية → دعوة الفريق → جولة سريعة.
- توحيد المكوّنات: جداول/نماذج/أزرار + حالات (تحميل/فراغ/خطأ) + تجاوب الجوال.

### المرحلة D (لاحقاً) — النضج التشغيلي
- بحث عام، تصدير موحّد، تحسينات أداء، تدقيق وصول موسّع.

---

## 5. مؤشّرات النجاح
- مستخدم جديد يتنقّل بين أي وحدتين **دون العودة للوحة الرئيسية**.
- مدير الجمعية يفهم «من يصل لماذا» من شاشة واحدة.
- جمعية جديدة تُكمل التهيئة وتدعو فريقها **دون مساعدة فنية**.
- اتساق بصري كامل عبر كل الصفحات + عمل سليم على الجوال.

---

## 6. الخطوة التالية
نبدأ بـ**المرحلة A (هيكل التطبيق الموحّد)** لأنها أكبر أثر مباشر على الإحساس بالتماسك والمتانة،
ثم B فـC بالتوالي. (التشغيل الفعلي ببيانات حقيقية يبقى مشروطاً باستضافة سعودية + DPA + DPIA + فتح البوابة.)
